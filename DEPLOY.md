# Развёртывание на Netlify

Пять шагов, примерно полчаса. **Node на вашей машине не нужен** — сборку Netlify
выполняет у себя, схему базы вы применяете через браузер.

Что понадобится: аккаунт GitHub, аккаунт Netlify, аккаунт Neon. Все бесплатные.

---

## 1. База данных

1. Зарегистрируйтесь на <https://neon.tech> и создайте проект. Регион — ближайший
   к пользователям; для Кыргызстана это Frankfurt (`eu-central-1`).
2. Откройте **SQL Editor**.
3. Вставьте целиком содержимое `db/schema.sql` и выполните. Создадутся четыре
   таблицы и два типа-перечисления.
4. Вставьте целиком `db/seed.sql` и выполните. Появятся организация,
   пользователь и один заполненный документ.
5. На вкладке **Connection Details** скопируйте строку подключения. Возьмите
   именно **Pooled connection** — адрес хоста в ней содержит `-pooler`.
   Строка должна оканчиваться на `?sslmode=require`.

> Приложение уже настроено под пулер: в `db/index.ts` на бессерверном хостинге
> включается `prepare: false` и одно соединение на процесс. Без этого запросы
> падают на втором обращении.

---

## 2. Репозиторий на GitHub

Создайте пустой репозиторий (без README и .gitignore — они уже есть), затем
в терминале:

```sh
cd ~/tapshyrma
git add -A
git commit -m "Конструктор ТЗ: скелет, движок правил, экспорт в DOCX"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/tapshyrma.git
git push -u origin main
```

При запросе пароля GitHub нужен не пароль, а токен: **Settings → Developer
settings → Personal access tokens → Tokens (classic)**, право `repo`.

Репозиторий сделайте **приватным**: в `db/seed.sql` лежит хеш пароля учётной
записи.

---

## 3. Сайт на Netlify

1. <https://app.netlify.com> → **Add new site → Import an existing project → GitHub**.
2. Выберите репозиторий `tapshyrma`.
3. Команду сборки и каталог публикации Netlify возьмёт из `netlify.toml` —
   менять ничего не нужно. Плагин для Next.js подключится сам.
4. **Не нажимайте Deploy сразу** — сначала переменные окружения (шаг 4).

---

## 4. Переменные окружения

**Site configuration → Environment variables → Add a variable**, две штуки:

| Имя | Значение |
| --- | --- |
| `DATABASE_URL` | строка подключения из шага 1 (pooled, с `?sslmode=require`) |
| `SESSION_SECRET` | случайная строка от 32 символов |

Секрет сгенерируйте так:

```sh
python3 -c "import secrets; print(secrets.token_hex(32))"
```

Теперь запускайте сборку: **Deploys → Trigger deploy → Deploy site**.

Первая сборка идёт 2–4 минуты. Адрес будет вида `случайное-имя.netlify.app`;
переименовать — **Site configuration → Change site name**.

---

## 5. Сразу после первого входа — смените пароль

Вход из сида: `drafter@example.kg` / `tapshyrma`. Этот пароль знает каждый, кто
видел репозиторий, поэтому меняйте его до того, как адрес станет известен
кому-то ещё.

Интерфейса смены пароля пока нет (он появится вместе с управлением
пользователями, этап 11 плана). Пока так:

```sh
python3 scripts/password-hash.py 'ваш-новый-пароль'
```

Скрипт посчитает хеш тем же алгоритмом, что и приложение, и напечатает готовый
`update` — выполните его в SQL-редакторе Neon. Считает около сорока секунд:
это чистый Python, потому что в системном Python на этой машине нет scrypt.

## Что делать, если сборка упала

- **`Не задана переменная DATABASE_URL`** — переменная не добавлена либо добавлена
  после запуска сборки. Добавьте и запустите повторно.
- **`SESSION_SECRET не задан или короче 32 символов`** — то же самое.
- **Ошибки типов при сборке** — на машине разработки не было Node, и `npm run
  typecheck` ни разу не запускался. Netlify покажет файл и строку; пришлите
  вывод, поправлю.
- **Запросы падают на втором обращении** — взята прямая строка подключения
  вместо pooled. Замените на адрес с `-pooler`.
- **502 или таймаут на страницах со списком документов** — исчерпан лимит
  соединений Neon. Проверьте, что в строке именно pooled-хост.

## Чего в этом развёртывании ещё нет

- Управления пользователями и организациями: учётные записи заводятся в базе.
- Маршрута согласования между пятью ролями — роли есть в схеме, но ни на что
  не влияют (этапы 11–12 плана).
- Слоя AI и сравнения версий: они пока есть только в браузерном демо.
- Вывода документа на фирменный бланк органа и экспорта в PDF.

## Про размещение данных

Netlify и Neon — за пределами Кыргызстана. Для демонстрации и пилота без реальных
персональных данных это приемлемо, но при внедрении в государственном органе
вопрос трансграничной передачи встанет: см. раздел 07 плана продукта.
Архитектура переносимая — обычный Node и PostgreSQL, никаких API конкретной
платформы, — поэтому переезд на VPS в Кыргызстане стоит около недели работ.
