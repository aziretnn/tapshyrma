# Тапшырма — заметки для работы над кодом

Конструктор ТЗ на ИТ-системы по ГОСТ 34.602 для госорганов КР. Next.js (App Router),
PostgreSQL + Drizzle, интерфейс и весь текст — по-русски.

## Инварианты, которые нельзя нарушать

1. **Ссылки на нормативные акты берутся только из `lib/reference/legal-acts.ts`.**
   Никакого написания реквизитов по месту, никакой генерации моделью. Раздел 9 документа
   собирается функцией `sourcesFor()` в `lib/tz/derive.ts`. Ошибка в реквизитах закона —
   это испорченный документ и отменённая процедура закупки, а не косметический дефект.

2. **Версия документа не перезаписывается.** Сохранение всегда добавляет строку в
   `document_versions`. Утверждённая версия (`status = approved`) неизменяема.

3. **Документ выводится из модели, никогда наоборот.** `components/Preview.tsx` не содержит
   редактируемых полей. Единственный источник содержания — `TzModel`. Рендереров два —
   экран и `lib/export/docx.ts`; словесные формулировки они берут из общего
   `lib/tz/vocabulary.ts`, иначе документ на экране и документ в файле разойдутся.

4. **`lib/tz/derive.ts` и `lib/rules/engine.ts` — чистые функции.** Никаких запросов, дат
   «сейчас», случайности: одна и та же модель обязана давать один и тот же документ и один
   и тот же набор замечаний, иначе сравнение версий врёт, а аудит невоспроизводим.

5. **Решение о выпуске документа принимает движок правил, а не языковая модель.** Когда
   появится слой AI (этап 9–10), он пишет текст и предлагает переформулировки — но никогда
   не определяет, блокировать документ или нет. Блокирующее замечание нельзя обосновать,
   только устранить.

## Где что менять

- Новый вопрос анкеты → только `lib/questionnaire/steps.ts`. Интерфейс трогать не нужно:
  `components/Field.tsx` рендерит поле по его декларативному описанию.
- Новое правило → `lib/rules/rules.ts` плюс строка в таблице README. Правило, для которого
  в модели ещё нет данных, добавляется с `implemented: false`, а не пропускается: реестр
  должен показывать и то, что не проверялось.
- Ключ замечания (`Finding.key`) обязан быть стабильным: по нему хранится обоснование.
  Если ключ меняется от правки соседнего поля, обоснование молча теряется.
- Новый раздел документа → правится в двух местах сразу: `components/Preview.tsx`
  и `lib/export/docx.ts`. После правки прогнать `npm run check:docx`.
- Демонстрационный документ живёт в `lib/tz/example.ts` и используется сидом и обеими
  самопроверками. Отдельных копий примера заводить не нужно.
- Новое поле документа → сначала `lib/tz/model.ts` (zod-схема), потом анкета, потом превью.
  Все поля имеют умолчания, чтобы старые снимки из базы читались без миграции.
- Чтение из базы → `lib/documents.ts`. **Не** в файл с `"use server"`: каждый его экспорт
  становится вызываемой с клиента точкой, и запросы на чтение такой точкой быть не должны.
- Организация проверяется в каждом запросе к документам: документ одного органа не может
  открыть пользователь другого.

## Проверки перед тем, как сказать «готово»

`npm run typecheck` и `npm run check` ловят типы и логику, но не поведение
в браузере. Всё, что связано с обработчиками, гидратацией и браузерными API,
проверяется только `npm run smoke` — и обязательно **по сетевому адресу**,
а не только по localhost: `http://localhost` считается защищённым контекстом,
а `http://10.0.0.187:3000` — нет, и часть браузерных API там отсутствует.
Именно так пропустили падение `crypto.randomUUID` в `lib/tz/path.ts`.

## Терминология

Пишите так, как говорят закупщики, а не разработчики: «техническое задание», а не «спека»;
«функциональное требование», а не «фича»; «критерий приёмки», а не «acceptance criteria»;
«орган», а не «клиент». Незаполненное место в документе показывается явно квадратными
скобками — документ должен честно показывать пробел, а не прятать его.

## Чего в скелете намеренно нет

Автосохранения (версия создаётся осознанно), внешних UI-библиотек (обычный CSS с токенами
в `app/globals.css`), NextAuth (своя cookie-сессия в `lib/auth.ts` — заменяется на вход по
учётной записи органа на этапе 11), библиотек для DOCX и ZIP (`lib/export/` — свой код).

Индикатор полноты в мастере считает заполненность, а не соответствие нормам: это разные
вещи, и путать их в интерфейсе нельзя. Соответствие считает движок правил.

Ещё не сделано: слой AI (этап 9–10), маршрут согласования и сравнение версий (11–12),
вывод на фирменный бланк органа и PDF.
